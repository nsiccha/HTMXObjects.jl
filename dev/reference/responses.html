HTMXObjects.MARKDOWN_URL_RULE Constant

MARKDOWN_URL_RULE

The stock MarkdownRule: a bare http(s):// URL becomes an anchor whose label is the URL itself. Trailing sentence punctuation is trimmed off the link (GFM's rule) and re-emitted as text.

DefaultMarkdownRenderer()

The stock MarkdownRenderer: CommonMark plus the GFM table, strikethrough and task-list extensions rendered into plain h nodes, exactly as render_markdown behaved before renderers existed. render_markdown uses it unless the caller passes renderer=.

HTMXObjects.Glossary Type

Glossary(terms; href="", title="Glossary") Glossary(["topic" => terms, …]; href="", title="Glossary")

An app's glossary: its GlossaryTerms (a "term" => "definition" pair stands for a term without other forms) and href, the address of the page that shows it with glossary_section. A term's link is href * "#term-<id>"; with the default href="" the links point into the page they are on, for a glossary on the same page. title heads the glossary section and the glossary a pdf_report appends; write it in the app's language ("Glossar").

HTMXObjects.GlossaryTerm Type

GlossaryTerm(term, definition; forms=String[], id=nothing, also=String[], see=String[], private=false)

One entry of a Glossary: term as the glossary lists it and its definition, a plain-text sentence or two. forms are the other spellings that link to the entry where they appear in a page, such as a German plural or an inflected phrase ("Registerzellen", "Modells vor dem Benchmarking"); a form also matches with its first letter capitalized, as at the start of a sentence. id names the entry's address, #term-<id>; left out, it is built from term ("Teilverkehrszelle" → #term-teilverkehrszelle).

HTMLDocument(root::Node)

A complete HTML document: the <html> element root plus the <!DOCTYPE html> preamble that must precede it in the serialized bytes. This is what htmx returns — and therefore what pico_page and every __page__ built on them return.

HTMXObjects.HTMLSnapshot Type

HTMLSnapshot(value)

Serialize value's HTML once, at construction, and keep value for every other projection. Use it when an application retains a generated surface across responses: an HTML response or HX swap writes the stored bytes, while ?plain/?markdown/Accept: text/markdown, ?error and static export project the retained value exactly as if the route had returned value itself. One build serves every projection.

HTMXObjects.MIMEResponse Type

MIMEResponse(content_type, body)

Small wrapper for routes that return non-HTML content (JS, JSON, CSS, SVG, plain text, etc.) without hand-rolling an HTTP.Response. _resolve_response converts it to HTTP.Response(200, ["Content-Type" => content_type]; body). The recording flow's _save_typed_response then dispatches on Content-Type to pick the right file extension (.js for application/javascript, .json for application/json, etc.). One line, fully recordable, MIME-aware.

HTMXObjects.MarkdownOnly Type

markdown_only(text)

Wrap text that should only appear in markdown responses. In HTML mode, this is invisible (renders as empty string). Use for structured markdown output (code blocks with markers, custom formatting) that has no HTML equivalent.

HTMXObjects.MarkdownRenderer Type

MarkdownRenderer

Abstract renderer for render_markdown: an app subtypes it and adds markdown_node methods for only the CommonMark node kinds it cares about, and every other kind falls through to the stock method. The walk recurses through the SAME renderer at every depth — children, joined text runs, tight-list items, table cells — so an override applies inside lists, quotes and tables.

source
HTMXObjects.MarkdownRule Type

MarkdownRule(pattern, build)

One inline text rule for render_markdown: pattern is matched against each joined text run outside links, code and fences, and build(match::RegexMatch, context) builds the replacement — a node, a String, or a vector of nodes and strings spliced in place.

HTMXObjects.SemanticAction Type

SemanticAction(label, target)

An OPERATION offered to the reader, as opposed to a SemanticLink's plain navigation. The HTML projection carries the hx-* attributes that make it an in-place HTMX swap; every other format degrades to an ordinary link, which is the point — the meaning stays readable where hx-get is not.

source
HTMXObjects.SemanticAlternatives Type

SemanticAlternatives(default, ("label" => view)...)

Several views of the same content — a verbatim source and its rendered preview, a summary and its full body. The first view is the DEFAULT: it renders directly, and it is the ONLY view in the Markdown, plain and HXML peers. Every later view renders collapsed inside a native <details> with its label as the <summary> — view-switching with no client JavaScript. A later view with nothing to show its reader, such as private content without a stand-in for a public reader, is left out together with its label.

A downloadable payload: a name, a MIME type, and a PLACE to fetch it from. bytes stays positional and optional because an artifact is sometimes a payload the route already holds and sometimes just a name for what a URL will produce.

HTMXObjects.SemanticDisclosure Type

SemanticDisclosure(summary, children...)

Content the reader OPENS — not content that is hidden. The distinction is per format and is exactly why this cannot be an h.details wrapper around semantic children: HTML collapses it, but Markdown and plain text have no viewport to collapse into, so their correct projection is the label followed by the whole body. Wrapping semantic children in markup instead would force the entire subtree down the HTML→Markdown translation path and lose every peer projection underneath it.

SemanticProse(markdown; math=true) SemanticProse(doc::Markdown.MD; references=Dict(), math=true) SemanticProse(doc::Base.Docs.DocStr; references=Dict(), math=true)

HTMXObjects.generic_html Method

generic_html(val) -> Node or ""

Structured, escape-safe HTML for an ordinary Julia value whose type defines no show(::IO, ::MIME"text/html", …) method. This is the framework's generic presentation contract: a route may return plain data (a NamedTuple of results, a Dict, a count) and still render in HTML/HX mode, the same way ?plain markdown mode already renders any value via show(::MIME"text/markdown").

HTMXObjects.glossary_script Method

glossary_script()

Client runtime of the term links link_terms writes, and of the ⓘ after an explained column's label (ColumnSpec help). Hovering a term or focusing its link opens the term's definition beside it; the runtime places the box below the term (above it when there is no room below), inside the window, and outside any scrolling container such as a wide table's, which would otherwise clip it, and keeps it there while the page scrolls. Escape closes it until the pointer or the focus leaves the term.

HTMXObjects.glossary_section Method

glossary_section(g::Glossary; level=nothing)

The glossary as a section headed g.title: each term with its definition, at its address #term-<id>, alphabetically, or for a glossary given by topic, each topic as a section of its own, in the order written. An entry shows the term's other names (also) and ends with links to its related entries (see), labelled in the page's language (Also: / See also:, Auch: / Siehe auch: under __lang__ = "de"). A link that opens an entry highlights it. A private entry is marked for a private reader and left out of a public answer; so is a topic whose terms are all private, its heading included.

html_escape(s) -> String

HTMXObjects.htmx Method

htmx(body...; htmx_version="2.0.8", sse_version="2.2.4", ws_version="2.0.4", hyperscript_version="0.9.14", preload_version="2.1.2", pico_version=nothing, pico_color=nothing, katex_version="0.19.0", prism_version="1.30.0", assets=:cdn, runtime=:inline, feedback=true, thread=true, tables=true, extra_head=(), error_texts=nothing, lang=nothing, title=nothing)

Generate a full HTML page with HTMX and optionally Hyperscript/PicoCSS loaded from CDN. Pass nothing to any version kwarg to skip that library. lang is the page's language as a BCP 47 tag ("de", "de-CH", "en-GB"), written as <html lang>: screen readers pronounce the page in it and CSS hyphens: auto hyphenates by it. title is the page's <title>. Left at nothing, each takes the __lang__ / __title__ that a struct on the route's mount chain declares (the innermost declaration wins), so a subtree can give its own pages a language and title the root's shell does not know; with neither, the page has no lang attribute and no <title>. A string that is not a language tag, or a title that is not a non-empty string, throws an ArgumentError, and so does a title alongside an h.title in extra_head (a page has one <title>). sse_version is htmx's SSE extension, which sse_region needs; it loads only alongside the shell's own htmx (an extension must follow htmx). ws_version is htmx's WebSocket extension, which @ws routes need on the client (a ws-connect element); it loads only alongside the shell's own htmx for the same reason. The shell always carries stream_probe_script, so a ws or sse stream refused by an auth gateway reloads the page on the gateway's HX-Refresh instead of reconnecting forever. It also carries modifier_click_script: a Ctrl/Cmd- or Shift-click on an htmx link with a real href opens that address in a new tab or window, as on any link. Set feedback=false to disable automatic request feedback (pulsating borders, success/error flash). Set thread=false to leave out the live_thread runtime.

HTMXObjects.link_terms Method

link_terms(value, glossary::Glossary)

value with the uses of glossary's terms linked to their entries: in each section of a page (a heading, section or SemanticSection starts one), and again in each table, figure, caption and disclosure, the first use of a term becomes a link to glossary.href * "#term-<id>". Hovering it or focusing it shows the term's definition beside it, and screen readers read the definition as the link's description. HTMXObjects.markdown_children Method

markdown_children(renderer, node, rules, context) -> Vector

Render node's children with joined text runs, ready to splat into an h parent. Adjacent Text children render as ONE run (see MarkdownRenderer); a Backslash node is a zero-width escape marker — the escaped char arrives as the following Text — so joining skips over it rather than splitting the run. Rules therefore see escape-RESOLVED text and cannot tell \#12 from #12.

HTMXObjects.math_script Method

math_script()

Client runtime that typesets the TeX math render_markdown marks: every .htmxo-math element, rendered with KaTeX's renderToString (throwOnError: false, trust: false) on load and after every htmx swap. Only marked elements are typeset; the page's text is never rescanned for delimiters, so code stays literal.

HTMXObjects.math_styles Method

math_styles()

<style> block for the math math_script typesets: a display formula is a block that scrolls sideways when it is wider than its column, and a formula not typeset (yet, or without KaTeX) shows its TeX source in a monospace font, so it reads as source rather than prose. Scoped under @layer htmxo, so host stylesheets win. Auto-included by htmx.

source
HTMXObjects.modifier_click_script Method

modifier_click_script()

Client runtime that gives Ctrl-, Cmd- and Shift-clicks on htmx links back to the browser. htmx takes over every click on an <a href> that carries hx-get (or another request attribute), modifier clicks included, and swaps in place; its own exemption covers only Ctrl/Cmd-clicks on boosted links. With this runtime, a Ctrl/Cmd- or Shift-click on such a link — as nav_sidebar, htmxo_breadcrumb and hx_link render — opens its href in a new tab or window and leaves the page as it is: no request, no swap, no history entry. The click stops before any of the link's own click handlers (such as nav_sidebar's active-link highlight). A plain click still swaps in place, and a middle-click, which htmx never sees, still opens the href.

source
HTMXObjects.redirect_history_script Method

redirect_history_script()

Client runtime that records a redirect's destination in the browser history. htmx's request follows a redirect (redirect_to) and swaps the new route's fragment, but a link whose hx-push-url (or hx-replace-url) names the requested URL itself — as nav_sidebar's links do — would still record the old URL. When htmx is about to record such a URL for a request that was redirected within the same origin, this runtime records the destination instead: its path, and its query unless the recorded URL carried a query of its own different from the request's. Any other history entry — hx-push-url="true" and boosted links, which htmx already points at the destination, or a URL naming another page — is left as it is.

HTMXObjects.syntax_script Method

syntax_script()

Client runtime that highlights code with PrismJS: every <code class="language-…"> element, such as a SemanticCode or a Markdown code fence that names its language, on load and after every htmx swap, so code in a lazily loaded tab, a disclosure or an in-place demo is highlighted like code in the page itself. HTMXObjects.unit_view_control Method

unit_view_control(doc; param="layer", id=nothing)

The switch that reads a page at one layer: "all layers" (the default) or one layer alone, for every unit of the page, in the browser and with no request. The choice stays in the page address (?layer=short), so a link, a reload and a static export keep it. Radios, so the arrow keys choose.

HTMXObjects.wants_markdown Method

wants_markdown(req::HTTP.Request) -> Bool

Return true if the client wants a markdown response (for LLM/CLI consumption). Checks for Accept: text/markdown or text/plain header, or a ?plain / ?markdown query parameter.
