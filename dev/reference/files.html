HTMXObjects.EditorRoutes Type

EditorRoutes

Git-backed inline editor @htmx struct. Mount as an @include under a parent that exposes editor (a per-file handle, normally GitRepo(path).editor(relpath)) and container_id::String (HTML id of the wrapper) as locals. All URLs forward the parent's @param values via query_url(path, __parent__), so a parameterised parent (@param name::String picking which file to edit) survives edit/save/cancel/history/restore round-trips with no extra wiring.

HTMXObjects.Gallery Type

Gallery(gallery_dir)

Walks gallery_dir recursively and builds one GalleryItem per .jl file. Reads section titles from _section.md files in each subdirectory (first non-empty line, or title: … key/value).

HTMXObjects.GalleryItem Type

GalleryItem(path)

Single gallery entry parsed from a Julia source file at path. Reads the metadata header (# key: value lines) and captures the rest of the file as code_string. The body is Base.include-able by the app so it can be eval'd to produce a value (Vega-Lite spec, Stan model, formula text, …) the app's renderer turns into HTML.

HTMXObjects.PrivateContentEscaped Type

PrivateContentEscaped <: Exception

Thrown when a public answer (a public static export or dispatch(...; audience=:public), a recording, a public pdf_report) still holds content marked private: markup rendered for the live app before the export could leave it out, such as a Raw string built from repr("text/html", …) or an HTMLSnapshot held inside a value the export cannot walk. Render that markup from the value instead, or build it for the request's export_audience.

HTMXObjects.StaticExportRefused Type

StaticExportRefused <: Exception

Thrown by dispatch(...; static=spec) when the route returned a finished HTTP.Response, MIMEResponse or JSONResponse. Such a response bypasses the static transform, so returning it would put live markup into a static bundle; the handler rethrows instead of rendering an ordinary route error, so the export fails at the dispatch call.

source
HTMXObjects.StaticSiteIncomplete Type

StaticSiteIncomplete <: Exception

Thrown by export_site once its crawl has finished, when the bundle is not complete: failed lists each address whose answer could not go into it (address => reason: a status other than 200, an X-HTMXO-Error-Id header, no file extension for its Content-Type, a file another address already took), unresolved each reference in a written HTML file that names no file of the bundle (file => address, file the page's path in the bundle with / separators on every platform). files and bytes count what was written into dir.

HTMXObjects.copy_vendorfiles Method

copy_vendorfiles(dir; packages=(:htmx, :sse, :ws, :preload, :hyperscript, :pico, :katex, :prism), runtime=true, pages=nothing) -> Vector{String}

Copy the vendored head assets — the same files vendorfiles serves — into dir (created if missing), for a static bundle that has no routes to serve them from. packages selects which pinned libraries to copy; :pico is pico.min.css and every colour build beside it (pico.<colour>.min.css, for pico_color), and :katex is the directory dir/katex/ (stylesheet, script and fonts) that typesets Markdown math on pages whose assets prefix names dir, and :prism the directory dir/prism/ (core, autoloader and every language's grammar) that highlights their code. With runtime=true (the default) HTMXObjects' own page runtime is copied too, to dir/htmxo/<name>.css|js — the files a runtime=:linked page links (see htmx), including the Treebars poll assets while that extension is loaded — so StaticExport(; runtime=:linked) pages can link one shared copy instead of carrying the runtime inline. The written paths come back with the libraries first, in load order. Existing files are overwritten, and the copies are ordinary writable files (the artifact store is read-only). Like vendorfiles, the first call downloads the pinned npm tarballs.

HTMXObjects.export_audience Method

export_audience(req::HTTP.Request) -> Symbol

Who the answer to this request is for: :public or :private. A request of the live app is :private, since the live app shows everything. A dispatch answers for the audience it was given, else its StaticExport's (:public unless asked otherwise), else the audience of the request it is made in, and :public outside any request. private content shows its public stand-in, or nothing, in a :public answer.

HTMXObjects.export_site Method

export_site(dir; pages, file_name=static_file_name, controls=:remove, aliases=Dict{String,String}(), parent=nothing, audience=:public, parallel=<threads ≤ CPUs>) -> (; files, bytes)

Write the mounted app into the new or empty directory dir as a static site that any static file server shows as it is, from the bundle's root or from a subdirectory (https://<user>.github.io/<repo>/), with no server-side code. route! must have registered the app; no listener is needed, and the export can run inside a serving app (it renders in process with dispatch(...; static=StaticExport(...)), which re-registers nothing).

HTMXObjects.pdf_report Method

pdf_report(markdown::AbstractString, pdf_path; title, lang, metadata=(;), base_url=nothing, url_map=nothing, resources=dirname(abspath(pdf_path)), quarto="quarto", audience=:public, glossary) -> pdf_path pdf_report(value, pdf_path; audience=:public, glossary, kwargs...) -> pdf_path

Write a report as an accessible PDF (PDF/UA-1, ISO 14289-1) at pdf_path. The input is Markdown, typically a page's own projection: a value such as an h.article(...) is converted with to_markdown_string, and the body of dispatch(:GET, "/report"; headers=["Accept" => "text/markdown"]) is passed as it is. Tables, figures and captions keep their structure: header rows become table header cells, captions stay attached to their table or figure. A table longer than the rest of its page continues on the next, its header row repeated, and a caption above it moves along with its first rows. A code block is one tagged Code element with a paragraph per line, in the colours of Quarto's arrow theme; a blank line in it is kept on the page and left out of the tags. Quarto's own highlighting tagged each token as a Code element of its own, and PAC (PDF Accessibility Checker) warned about the empty and whitespace-only ones. Semantic disclosure labels (including eager tabs and master-detail labels) stay with the start of their body. Their Markdown marks the label alone with ::: {.htmxo-label}; the body can continue across pages. Regenerate saved Markdown to get these markers. Ordinary bold prose keeps its own pagination.

HTMXObjects.record! Method

record!(app; record_dir, record_base="", paths=["/"], full=true, hx=true, markdown=true)

Drive each path through the in-process route handler with one or more header sets, writing recordings under record_dir. No subprocess, no HTTP listener — looks each path up via HTTP.Handlers.gethandler on ROUTER and invokes the handler with a manufactured HTTP.Request. The handler's existing save logic in _resolve_response writes the appropriate file shape.

The address a response should embed for address where a static export cannot rewrite it: inside a JSON payload, an inline script, or a Vega spec's data.url (an AlgebraOfVega geoshape(url) or data(url)). HTMXObjects.staticfiles Function

staticfiles(folder, mountdir="static"; headers=[], loadfile=nothing, bundle=false, private=false)

Serve every file under folder at /<mountdir>/<relative path>. An index.html also answers at its folder's address with a trailing slash; the address without one redirects (308) there, as on any static server, so the page's relative links resolve inside the folder. Files are read once, when mounted. headers are added to every response, and loadfile(path) replaces read(path).

HTMXObjects.url_anchor_script Method

url_anchor_script()

Client runtime that lets the page address's #id land on its element while htmx is still loading the page's parts. The browser scrolls to the element the #id names while it loads the page, and keeps it there until the page's load event; what htmx swaps in after that moves the page on without it. An element a swap inserts — inside a fragment the page loads with hx-trigger="load", a lazy part, or a tabset such a fragment carries — misses the scroll, so the page stays at its top. An element the page carries is pushed down by a lazy part that loads above it, and stays short of the top when the page was too short to bring it there and its lazy content (a tab's panel) loads afterwards.
