HTMXObjects.CardDeckTexts Type

CardDeckTexts

The words of a card_deck: its accessible name (label), the view switch (view, grid, carousel), the search box (search) and its count (matches, with {shown} and {count}), the note shown when no card is left (no_match), the group filter (groups, all, and for a long list of groups group_search and group_no_match), and the carousel's buttons (previous, next) and position (position, with {position} and {count}). Build one with card_deck_texts.

source
HTMXObjects.LiveThreadTexts Type

LiveThreadTexts

The words a live_thread writes itself. The control above the items: older (it loads older items), older_loading (while a page loads), older_retry (after a page failed; a click retries) and start (nothing is older). The pill below: unseen (with {count}, the items that arrived since the reader scrolled up) and latest (the reader is far up and nothing new arrived). The status line: older_failed and refresh_failed (with {error}), whose error is timed_out, network_error or the server's answer (HTTP 500 (error <id>)), and response, the disclosure that holds a failed answer's body. Build one with live_thread_texts.

HTMXObjects.PdfPanelTexts Type

PdfPanelTexts

The words of a pdf_panel: its accessible name and pdf_toggle's text (label), the document chooser's name (documents) and, for a long list of documents, its search field (search, and no_match when no document matches), the page line (page, with {page} and {pages}), the bar's buttons (previous_page, next_page, colours, colours_help, open_file, close), the status line (loading, failed, not_found on a PDF's page, not_in_document in an HTML document, empty), and where the panel stands: the placement switch (placement, with beside, right and bottom), the edge that resizes it (resize) and the tab a closed panel leaves (reopen). Build one with pdf_panel_texts.

HTMXObjects.app_layout Method

app_layout(sidebar, content; content_id="content")

Two-column app shell — sidebar <aside> next to a main content column. Inspired by Pico's docs layout (CSS Grid with named areas, sticky inner nav, stacks on mobile <1024px). sidebar is rendered as-is (typically nav_sidebar); content is wrapped in <div class="htmxo-app-content" id=content_id> so HTMX swaps targeting #content work out of the box.

HTMXObjects.card_deck Method

card_deck(cards; id, view=:grid, search=true, group_filter=true, view_param="view", card_param="card", texts=nothing, class="", assets=true)

A deck of cards that the reader sees either as a grid or as a carousel (one card at a time, with previous and next), and switches between the two. A search box filters the cards by their words, a group filter by their group, and the carousel pages over the cards they leave. The view and the current card are kept in the page address, so a link opens the deck at a card.

HTMXObjects.htmxo_breadcrumb Method

htmxo_breadcrumb(items; target="#content", preload=nothing)

Render a Pico-styled breadcrumb <nav>. Each item is a tuple (label, frag_url, push_url). When frag_url is nothing, the segment renders as plain text (the current page). Otherwise it's an <a> that issues hx-get=frag_url into target and updates the URL bar via hx-push-url=push_url. The link's href is the address it records — push_url, or frag_url for push_url="true" — so a Ctrl/Cmd-, Shift- or middle-click opens that page in a new tab or window (on an htmx page, see modifier_click_script), and the link is reachable by keyboard. A segment that records no address (push_url nothing or "false") has no href. preload=true starts fetching a segment while the pointer rests on it (see hx_link).

HTMXObjects.htmxo_utility_styles Method

htmxo_utility_styles()

<style> block with HTMXO's small utility-class set. Replaces inline style="..." on common patterns: visibility, cursor, flex/grid layout, spacing, typography, and theme-aware text colors. All classes are scoped under @layer htmxo so host stylesheets always win on conflict. Two rules are intentionally unlayered so they beat Pico's unlayered button rule: the generic in-flight .htmx-request rule (cursor: progress), and the reset that renders a sortable_table header's sort <button> as plain heading text with a focus ring.

HTMXObjects.live_thread_page Method

live_thread_page(items; cursor=nothing)

Response fragment for a live_thread's older_url: the page of key => content items (oldest first) directly before the requested cursor, plus the cursor of the page before this one — nothing once the start of the thread is reached. Items whose keys the client already holds are skipped, so overlapping (inclusive) cursors are fine; a page that neither adds items nor advances the cursor is reported as an error rather than retried forever.

HTMXObjects.live_thread_styles Method

live_thread_styles()

CSS for live_thread. Layout rules sit inside @layer htmxo so host styles win; the "new messages" pill is styled unlayered (like compose_box_styles) because Pico styles <button> unlayered, which would otherwise beat every layered rule and blow the pill up to a full button. HTMXObjects.live_thread_tail Method

live_thread_tail(items; since, version, reset=false, cursor=nothing)

Response fragment for a live_thread's tail_url: every item after the since key the client sent, in order, with the new since (key of the newest final item) and version. HTMXObjects.overlay_bar_script Method

overlay_bar_script()

JS for the overlay bar (D1 + D3). On DOMContentLoaded it builds the strip DOM, resolves where-you-are from window.location (proxied /p/<slug>/… → slug from the path; direct → app via /agents/app-for-port?port=), and attaches document.body htmx-event listeners: route tracking through partial swaps (htmx:pushedIntoHistory / htmx:historyRestore / popstate / htmx:afterSettle) and a traffic observer (htmx:afterRequest / htmx:sendError) that captures a FAILED app request — reading the X-HTMXO-Error-Id response header — as pre-filled bug context. The report posts raw context to the root-absolute POST /agents/report; the KB resolves the owner and files the todo.

HTMXObjects.pdf_beside Method

pdf_beside(content, panel; placements=(:beside,), placement=first(placements), class="")

content with the pdf_panel panel beside it: while the panel is open the two share the width (the panel 40 %, at least 22rem; set --htmxo-pdf-width to change it) and the panel stays in view while the content scrolls by, below a page's own sticky header (--htmxo-sticky-top) and above a bar fixed along the window's bottom (see pdf_overlay). Closed, the content has the whole width. Opening or closing it keeps the reference clicked last (else the content at the top of the window, below a table's sticky header) where it was on screen while the content wraps anew.

HTMXObjects.pdf_panel Function

pdf_panel(documents=(); id, link=id, texts=nothing, pdfjs, class="", assets=true)

A side panel that shows a document beside the content that quotes it, with the passage of every pdf_ref to it marked in the reference's colour. A PDF is every page of the file one below the other, each drawn as it comes into view (PDF.js, loaded from jsDelivr the first time the panel shows a PDF), each passage marked on its page. An HTML document (kind=:html) is the fragment its address answers to an htmx GET, as an htmx page would swap it in: its code is highlighted as the page highlights code, and each passage is marked over its words without changing the fragment. It starts closed. A reference's click opens it at its passage, a pdf_toggle shows and hides it, and its bar has the document chooser, the page line with previous and next page, "Colours" (each passage in its own colour, or only the passages pointed at and gone to), a link that opens the file itself and a close button. pdf_beside places it beside the content, pinned while the content scrolls by; pdf_overlay floats it over the page, on the right or below. Either can offer the reader a switch between those placements, and the panel's inner edge resizes it.

HTMXObjects.pdf_ref Method

pdf_ref(text, url; page=nothing, panel, quoted=nothing, key=nothing, hue=nothing, document=nothing, kind=:pdf, attrs...)

A reference to a passage of a document: a link to url at page (url#page=12), or for an HTML document (kind=:html) to url as given, that, on a page with the pdf_panel panel, opens that panel at the passage instead, marked. It is a chip: always lightly highlighted in its colour, more strongly while pointed at, most strongly once clicked. A modified click (new tab, new window) and a page without the panel open the document itself. Its Markdown is the link, [text](url#page=12).

pdf_toggle(panel, label=nothing; texts=nothing, attrs...)

A button that shows and hides the pdf_panel panel (its id), pressed while the panel is open. Opened before any reference was clicked, the panel shows its first document at page 1. label defaults to the panel's texts.label in the page's language. HTML only.

HTMXObjects.tabset_script Method

tabset_script()

JS that keeps a tabset's open tab in the page URL and operates its tabs from the keyboard. A tab click replaces the tabset's URL parameter with the tab's name, and a page opened with that parameter — reloaded, reached with Back, or a shared link — shows the named tab. The arrow keys, Home and End move the focus along the tabs, and Enter or Space opens the focused one. Auto-included by htmx(); inject manually via extra_head (next to tabset_styles) if you're building your own <head>.

HTMXObjects.tabset_styles Method

tabset_styles()

CSS that draws tabset(...)'s <nav> + .tab-panel markup as an underline tab bar: a thin rule under the tabs, the other tabs in the muted text color (--htmxo-muted), and the open tab in the text color with an accent underline (--htmxo-accent) over the rule. The panel below is unframed. The rule's color is --htmxo-tab-rule, by default the text color at 20%; set it on .tabset (or :root) to change it.
